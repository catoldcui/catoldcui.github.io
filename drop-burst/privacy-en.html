2. What information we handle

2.1 Data kept on your device (not sent to us)

  • Save data: progress, unlocks, collection, records, settings (volume, language, haptics, reduce motion, the "Usage Analytics" switch, etc.), identifiers of purchased items, whether the free Daily Sea try has been used, your gem balance (with whether today's first Daily Sea try has been used and Apple's transaction identifiers of the gem purchases already credited, kept so the same purchase is never credited twice), the reminder schedule and choices described below, and data for resuming an unfinished dive. It is stored in the app's local storage, managed by the system. We run no server that holds a copy of it. The Game does not exclude the save from device backups, so if you use iCloud Backup or back up your device to a computer, the save (including your gem balance) is normally included in those backups; Apple or your computer handles them, and we never receive a copy.
  • Random install identifier: a randomly generated string created the first time the Game needs it and stored in the local save, used to group events from the same device in usage statistics (Google Analytics 4 calls it the client_id). It contains no name, email or device serial number, but it is a persistent identifier and is legally "pseudonymous" rather than fully anonymous data, so we disclose it together with the statistics in 2.3.
  • Local event log: only development / debug builds write an event log on the device; the release version you install from the App Store does not write this log, and on launch it removes any leftover log from older versions.
  • New-sea reminders (optional, if available in your version): if you turn reminders on (in Settings, or from the one-time offer after a Daily Sea), the Game asks iOS for notification permission and schedules local notifications on your device: at most 3 in any 7 days, at the time you choose, never between 21:00 and 09:00, and they stop if you stop playing. Reminders announce the Daily Sea, so they are only offered to players who own the Full Version. You can turn them off at any time in the Game or in iOS Settings. No push server is involved. If Usage Analytics is on, some players are randomly placed in a test group that gets no reminders (see 2.3).

2.2 Features you choose to use

  • Sharing: when you tap share, the Game builds text (which may include a challenge link and seed code) and a result image and hands them to the iOS share sheet. Where they go is your choice in the system sheet; our servers do not receive them.
  • Challenge links: the Game can open challenges through a custom link (such as yidi://). The link carries a game seed that recreates the same run and no personal information.
  • Feedback email: tapping "Send Feedback" opens your mail app with the game name, version and OS type (e.g. iOS) prefilled. Whether and what to send is up to you. We receive the content of the email and your email address.
  • Rating: the Game may ask iOS to show its rating prompt. We are not told whether you rated or what you wrote.
  • External links: tapping a link in Settings (such as the privacy policy web page) opens it in the system browser; that website then handles information under its own policy.

2.3 Usage statistics (Google Analytics 4; off by default in Europe, on by default elsewhere, can be changed at any time)

The Game records and uploads usage events to understand level difficulty, whether features are used, whether the purchase flow works, and whether reminders help players come back, so we can improve it. Events are received and processed by Google (Google Analytics 4). Events include (per what the code actually logs):

  • Launch and sessions: session start (with OS type, e.g. iOS), moving to background (with current screen).
  • Gameplay: run start / resume / abandon / end, mode, stage name, depth, diver, score and target, stars, taps used, best chain, weapons used and their levels, relics, reward and shop choices, buying and selling, collection and unlocks, opening and closing tutorial and help pages, showing and closing beginner tip cards (card name, time on screen in milliseconds, how it was closed), time from run start to the first drop tap (milliseconds).
  • Challenges and sharing: starting the "Daily Sea" or a challenge (including the game seed code), tapping share and the share-sheet result (shared / canceled), copying a seed code, opening a challenge link (link scheme type, and the error type when a link is invalid), requesting the rating prompt.
  • Settings: language change, setting changes (setting name and new value), Reset All Data (with whether you own the Full Version), opening Settings, tapping an external link in Settings (the link address).
  • Purchases: paywall shown and dismissed (source and reason), tapping buy, the product identifier (full for the Full Version, gems10 for the gem pack), whether purchase / restore succeeded and how many items were restored; no payment method, Apple ID or billing details, which we cannot receive anyway.
  • Gems: the gem purchase prompt being shown (gems_buy_show) and buy being tapped (gems_buy_tap), a gem pack being credited (iap_consumable, and gems_add with your gem balance and how many gems were added), a gem being spent on a Daily Sea try (gems_spend, with your balance afterwards), and the bonus gems that come with the Full Version (gems_gift, with your balance). These carry gem counts only.
  • Reminders (if available and you turn them on): turning reminders on or off (notification_opt_in with where you did it and the wording version, notification_opt_out with where), the iOS permission result (notification_permission_result: the authorization state and whether you allowed it), a reminder being scheduled (notification_scheduled: hours until it is due and the message template name) or canceled (notification_cancelled: reason and number canceled), and scheduling errors (notification_schedule_failed).
  • Reminder effectiveness test (only with reminders on and Usage Analytics on): once iOS allows notifications, the Game randomly assigns the install, on the device, to one of two groups: reminders as usual, or no reminders (the control group). The assignment is saved locally and logged once (notif_exp_enrolled: group and where you turned reminders on). After that the Game logs whether a reminder was opened (notification_opened: whether the app was closed at the time, the target screen, the template name, how many hours after it was due, and the group; notification_route_result: whether that screen opened, a short reason code and the group), and the first time you play in a new session after enrolling (notif_session_play: group, hours since enrolling, and whether it was a new dive, a Daily Sea or a resumed dive), plus, in the reminder group, a play within 24 hours of opening a reminder (notification_qualified_return: kind of play, hours and group). A new session is an app launch or a return after at least 30 minutes in the background. If you turn Usage Analytics off later, nothing more is sent, but the control group still gets no reminders until you use Reset All Data.
  • Technical problems: save-data migration, restore or corruption (version numbers or step only, never the contents), a failed attempt to resume an unfinished dive, the App Store purchase service being unavailable, and reminder bookkeeping problems (notif_write_fail, notif_clock_reset, notif_copy_missing: the failing step, hours the clock was set back, or the template name; never reminder contents).

Each event carries a timestamp, a session ID and the random install identifier above, plus, when the Game can work out your country, a two-letter country code (for example "CA"), taken from your App Store country or, if that is unavailable, from your device's region setting. It is a country only, never a city, address or GPS position, and the Game never asks for location access. Events do not contain your name, email, phone number, precise location, contacts or photos, and no advertising identifier (IDFA). Apart from the OS type, the Game does not deliberately put device model or OS version into events.

How it is sent and what Google sees: events are sent over HTTPS to Google's google-analytics.com. The network request itself lets Google receive your IP address, from which Google may infer an approximate region (per Google, GA4 does not log or store full IP addresses). The Game also sends the country code described above with the events, so that statistics can be broken down by country; Google gives a country supplied this way priority over one inferred from the IP address. We do not enable Google signals, ads personalization or data sharing with advertising products. While offline, events wait in a local queue (at most 500; the oldest are dropped when full) and are sent later; events still unsent after about 3 days are dropped because GA4 does not accept events that old.

How to turn it off: switch off "Usage Analytics" in Settings. After that the Game stops collecting and uploading statistics events, queued events not yet sent are cleared, and the local log of debug builds is deleted. Upload is controlled by this switch only (there are no ads, so there is no ad-consent flow). Turning the switch off does not erase historical data already uploaded to Google, and does not delete the random install identifier on your device (see Section 5). If you turn it back on, the same identifier is used again.

Default setting: if your region is an EU member state (including its outermost regions and Åland), Iceland, Liechtenstein, Norway, the United Kingdom or Switzerland, or if the Game cannot determine your region, "Usage Analytics" is off by default and nothing is collected or uploaded unless you turn it on in Settings; in other regions it is on by default. At launch, no statistics event is recorded or uploaded before the switch's state is settled; when the switch is off by default, launch events are simply discarded. Once you have turned the switch on or off yourself, the Game always follows your choice and no longer changes it by region. Your region is your App Store country; if that is unavailable, it falls back to your device's region setting. The same region gives the country code described above.

2.4 Purchases

In-app purchases are handled by Apple's StoreKit and the App Store. The Game has two products, and neither is a subscription or renews:

  • Full Version: a one-time purchase (a non-consumable item, product identifier full). It also includes 10 bonus gems, credited once per save.
  • 10 Gems: an optional pack (a consumable item, product identifier gems10). Gems are only offered to players who own the Full Version and are used for extra Daily Sea tries.

We do not receive or store your payment card details, Apple ID or billing address. The Game records on the device which products you bought, your gem balance and the Apple transaction identifiers of gem purchases already credited (see 2.1); this record is part of the local save and is not sent to us, although usage events can carry your gem balance and the number of gems added (see 2.3). The Game checks entitlements with Apple through StoreKit (including restoring the Full Version and revocation after a refund). Apple does not restore consumable purchases, so Restore Purchases does not bring gems back; on a new device or after reinstalling, gems come back only if the save itself is restored from a device backup (see 2.1). If a purchase needs a parent's approval through Apple's "Ask to Buy", that approval happens entirely on Apple's side and we receive no information about the parent or child.

  • To improve the Game: tune difficulty, fix problems, check that the purchase flow works and see whether reminders help players come back, based on usage statistics.

(Legal bases where GDPR applies: performance of our contract with you; for usage statistics, our legitimate interest in improving the product, which you can object to at any time with the switch in Settings; for feedback emails, your own initiative in contacting us.)

  • Apple (App Store, StoreKit, system share sheet, rating): handled under Apple's own policies.
  • The Game contains no ads and provides no data to any ad network.

  • Where legally required (for example valid legal process), we may disclose necessary information.

5. Retention and deletion

  • On-device data: kept until you delete it. "Reset All Data" in Settings (behind two confirmations) erases progress, pearls, unlocks, collection, records, Daily Sea scores, any unfinished dive, seen tips and story, language and all settings, the reminder schedule and your reminder test group (scheduled reminders are canceled), unsent usage events and the random install identifier (a new one is generated the next time it is needed). It keeps your purchases, your gem balance and whether the free Daily Sea try has been used, and keeps the "Usage Analytics" switch only if you had turned it off; otherwise the switch returns to the default for your region. Uninstalling the Game deletes all on-device data, including the random install identifier and your gem balance (the Full Version can be restored with Restore Purchases; gems cannot). If you restore the save from a device backup instead, everything in it comes back, including the random install identifier and your gem balance.
  • Statistics: kept on Google's side for the retention period we set in the GA4 console: 2 months. Google deletes them automatically afterwards.
  • Deletion per person is generally not possible: statistics events are tied only to a random install identifier. We have no account, email or similar data to identify you, and the identifier is not currently shown to you, so we usually cannot look up and delete "a particular person's" statistics. Reinstalling generates a new identifier, and the old one is no longer linked to your device.
  • Feedback emails: we keep correspondence for a reasonable time after your issue is handled; you may ask us to delete it.

7. Children's privacy

The Game is not designed for children under 13 (or, where the age of digital consent where you live is higher than 13, for example 16 in some EU countries, under that age), and it is not in the App Store "Kids" category. We do not knowingly collect personal information from such children.

To be clear about the facts: the Game has no accounts and neither asks for nor verifies age; the App Store age rating reflects content only and does not mean the Game is directed at children. "Usage Analytics" is on by default outside Europe, so if a child uses the Game, the usage events and random install identifier described in 2.3 are collected in the same way. A parent or guardian can switch off "Usage Analytics" in the Game's settings, or uninstall the Game to remove the identifier on the device. If you believe a child under 13 is using the Game and want our help, contact catoldinc26@gmail.com and we will do our best; because statistics cannot be traced to an individual, what we can mainly do is guide you to switch statistics off and explain the retention period, after which Google deletes the data automatically.

Contact for parents: catoldinc26@gmail.com.
